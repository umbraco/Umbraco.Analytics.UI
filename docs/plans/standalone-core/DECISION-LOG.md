# Decision log: Standalone core package

- 08-11-2026: The core package follows package major = CMS major, and Cloud aligns to the CMS's UUI and Lit versions. Why: one version line is simpler, and Umbraco sites are the main consumer.
- 08-11-2026: Swap points chosen at build time (`#platform/*`), not a runtime adapter. Why: the Umbraco package keeps its exact public types and behaviour; a runtime adapter would change 26 public element types.
- 08-11-2026: The core doesn't depend on `@umbraco-cms/backoffice`. Why: it carries its own Lit and UUI copies, so the portal would load them twice.
- 08-11-2026: Core translations, table context and fallback icons are our own small code, with no new dependencies. Why: keeps the core to Lit, UUI and Chart.js only.
- 08-11-2026: Swap points land first, pointing at the backoffice, before any core code. Why: the Umbraco package keeps working and its API report stays unchanged after every task.
- 08-11-2026: Tests flip to the core build (T12) only after every core swap point exists. Why: until then the core can't run the full suite.
- 08-11-2026 (T1): Swap points resolve through `package.json` `imports`; the library build also aliases `#platform/lit|uui|chart` straight to the external specifiers, because `export *` from an external module adds a namespace shim to the bundle. Storybook drops those aliases, since there the specifiers aren't external.
- 08-11-2026 (T1): `UauiLocalize.lang` is a method, matching `UmbLocalizationController.lang()`. The type lives in shared `src/platform/localize.ts` so both platforms use one copy.
- 08-11-2026 (T1): `UauiLitElement` is a named re-export of `UmbLitElement`, so the API report still says `extends UmbLitElement`. Accepted cost: a migrated bundle imports `UmbLitElement` under two names (~22 bytes).
- 08-11-2026 (T1): `@linkcode` defined in `tsdoc.json`, because API Extractor now reads lit-html's doc comments, which use it. Silences only that tag.
- 08-11-2026 (T1): `cleanse-pkg.js` removes the `imports` field from the published types package.
- 08-11-2026 (T2, user): Signed off the 2-line `api/analytics-ui.api.md` change, `import type { ReactiveController, ReactiveControllerHost }` → `import { ... }`. API Extractor drops `type` for names passed through a re-export; no effect for products. Rejected: a post-build rewrite of the emitted types to keep the line identical.
- 08-11-2026 (user): Byte-identical Umbraco output is a check during refactors, not a requirement. What must hold: the API report's meaning, behaviour, and the size budget.
- 08-11-2026 (T2): `src/examples/**` and `src/docs/*.mdx` keep the real specifiers, since they show product code and are published in the docs.
- 08-11-2026 (T2): `umbFocus` still comes from `@umbraco-cms/backoffice/lit-element` in the date range modal; T5 moves it with the modal.
- 08-11-2026 (T2): UUI theme CSS imports (`@umbraco-ui/uui/themes/*.css`) are allowed anywhere: assets, not code.
- 08-11-2026 (T2): Public TSDoc keeps saying `UmbLitElement`, since `UauiLitElement` isn't exported to products.
- 08-11-2026 (T2): The lint spec reaches ESLint through a Vitest browser command (`devops/lint-text-command.ts`), since specs run in the browser.
- 08-11-2026 (T3): Replaces the T1 "one copy" note. In the Umbraco build, `UauiLocalize` is `UmbLocalizationController` under our name (`import type { ... as UauiLocalize }` then `export type`), so the API report still prints `UmbLocalizationController`; other re-export forms changed the report. `src/platform/localize.ts` is now the structural contract: the core implements it, and the backoffice controller must satisfy it (checked in `swap-points.test.ts`).
- 08-11-2026 (T3): Interim `tsconfig.structural.json` + `src/platform/structural-check/` type-check the helpers against the structural `UauiLocalize`. Its file list is by hand, so a new helper taking `UauiLocalize` before T13 must be added to it. Removed in T13 when `tsconfig.core.json` checks all of `src/**` on core.
- 08-11-2026 (T4): `#platform/context` also carries the provider side (`UauiContextBase`, `UauiContextProviderHost`), so the table's context controller imports nothing from the backoffice. T8's core version provides the same names on a `ReactiveControllerHost & HTMLElement` host.
- 08-11-2026 (T4): `observe`'s callback gets `T | undefined`: it's called with `undefined` when the source is undefined, as the backoffice does. T8 must keep this.
- 08-11-2026 (T4): `UauiContextHost` uses `any` for the observe source and callback inside the host type only (tighter types stopped `UmbLitElement` fitting). The helpers' own signatures stay fully typed.
- 08-11-2026 (T4): Re-exports that keep `import type` in the API report: a separate `import type { X }` then `export type { X }`. `export type { X } from` prints `import`.
- 08-11-2026 (T5, user): Signed off dropping `constructor();` under `UauiDateRangeElement` in `api/analytics-ui.api.md`; the element no longer needs its own constructor. Rejected: an empty constructor kept only for the report.
- 08-11-2026 (T5): Test-only files may import `src/platform/umbraco/` by relative path until T12 (lint exempts them, nothing else). T12 moves `package-manifest.test.ts` and the test modal host into the `umbraco` Vitest project and deletes the `src/internal/test/modal-host.element.ts` shim.
- 08-11-2026 (T5): The date range dialog keeps its own working value; the Umbraco modal only receives the final value on Save. Focus moves in `firstUpdated` (Save when the range is valid, else the preset select), replacing `umbFocus` in shared code.
- 08-11-2026 (T5): For T9: `openDateRange` doesn't know which button opened it, so the core opener saves the focused element (through shadow roots) before opening and restores it after closing (R14).
- 08-11-2026 (T6): The core imports all of `@umbraco-ui/uui` (one import), not one package per element: it's a peer the host provides, so it costs nothing in the core bundle. T13 keeps `@umbraco-ui/uui` external and T16 lists it as one peer.
- 08-11-2026 (T6): `lit` `^3.3.3` and `@umbraco-ui/uui` `^2.1.1` are direct devDependencies, matching what CMS 19.0.0-beta1's lockfile resolves. Peer ranges come in T16.
- 08-11-2026 (T6): The core's `chart.ts` re-exports `chart.js` by name plus the look helpers from `src/external/chart.js/look.ts` (which imports nothing from the backoffice), not the products' entry.
