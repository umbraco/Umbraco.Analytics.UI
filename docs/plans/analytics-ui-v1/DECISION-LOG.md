# Decision log

- **30-10-2026** Skipped `feature-explore`'s interview. The proposal page and the code review of Engage, Commerce and AI already answered it, so `BRIEF.md` was written straight from them.
- **30-10-2026** v1 scope set from the Phase 1 design plus the three products' code. Added `uan-funnel` and selectable KPI tiles. Dropped the donut chart (not in Phase 1, one user) and the notes control (Engage-only).
- **30-10-2026** The Phase 1 export stands in for the devkit's per-screen mockups, because the deliverables are building blocks, not screens. Storybook is where they're reviewed.
- **30-10-2026** Base class `UmbLitElement` instead of `LitElement`, for localization and culture-aware number and date formatting. `uan-delta-badge` moves over.
- **30-10-2026** Charts and tables take numbers plus `Intl.NumberFormatOptions`, not formatter callbacks, so formats show in Storybook and stay consistent across products.
- **30-10-2026** Table supports both client and server paging. Engage needs server mode, and the smaller Commerce and AI tables shouldn't have to write paging code.
- **30-10-2026** KPI tile has one style and no `layout` property: the card with the icon in a pink square. Every Phase 1 screenshot uses it. The "filled-left" rail is only in the design notes and base CSS, never on a page, so it was dropped. An `inline` style for table totals was dropped too: a total is just a label and a number, so the product writes it in the table's `toolbar` slot. Adding a `layout` property later is non-breaking.
- **30-10-2026** No `uan-panel`. Panes are the backoffice's own `uui-box`, which has the headline, header actions, divider and padding control the design needs. A Storybook recipe keeps products consistent. The design's square 3px corners are dropped too: v18+ panels are rounded, so everything takes its radius from `--uui-border-radius-*` tokens.
- **30-10-2026** Conversion funnel parked, out of v1. No product would use it yet: Engage's is on Campaign Reporting (design only), and Commerce's cart conversion is a line chart that would need redesigning. It was also the most custom piece. Notes kept in SPEC.md "Later".
- **30-10-2026** Chart, compare, bars and markers are four sequential tasks (T9–T12), not parallel ones, because they all change `uan-time-series-chart`. The same goes for the table tasks (T15–T20).
- **30-10-2026** Specs for canvas-only chart outcomes (fills, dashes, bars) use Vitest's `toMatchScreenshot`, since a canvas has no DOM to assert on. Everything else asserts on the DOM, the hidden data table, the tooltip or events.
- **30-10-2026** Pending specs render elements by tag name and don't import element modules, so the suite compiles before the elements exist. A builder adds the static import when it turns a spec on.
- **30-10-2026** INT-1 has no Vitest spec. Its acceptance is a real CMS 19 backoffice (T21), since the import map and manifests only exist there.
- **30-10-2026** (T1 review) Colour tokens split into public `--uan-*` (products override) and private `--_uan-*` (elements read), so an ancestor's override isn't hidden by the element's own default.
- **30-10-2026** (T1 review) UUI palette colours don't change per theme, and the design's colours failed 3:1 contrast in one theme each. User chose to pair each default with a per-theme shade using `light-dark()`, keeping the design's colour where it reads. Design can adjust the pairs later.
- **30-10-2026** (T1 review) The token stylesheet moved to `src/internal/theme/` and isn't exported, so only the `--uan-*` names are public API. Changes PLAN.md T1's "Export from `src/theme/index.ts`".
- **30-10-2026** (T1 fix) `light-dark()` needs `color-scheme` set, and UUI's dark theme only sets `--uui-color-scheme`. Elements copy it on `:host`. Builder's colour picks: light series-2 maroon-flush, series-3 sunglow-dark, compare chamoisee (no orange reaches 3:1 on white); dark series-1 malibu-light, series-4 jungle-green (no violet passes on dark). Neutral tint is 20% of `--uui-color-text`. Table in `src/internal/theme/tokens.css.ts`.
- **30-10-2026** (T2 review) The package registers its translations at weight 200. Umbraco merges lower weights last, so a product's `localization` extension at the default 100 always wins. At equal weights the winner would depend on load order.
- **30-10-2026** (T2 review) Generic verbs reuse Umbraco's own keys (Save, Close, Loading, Search) instead of package copies, so they're translated in every backoffice language. The package only ships `en`.
- **30-10-2026** (T2 review) FND-2 specs use a test-only element until T4 and T13 exist. T4 and T13 now retarget them, so they end up testing shipped elements.
- **30-10-2026** User: the light-theme shades (mustard, tan, red-pink) feel dull; wants something more vibrant. Revisit when the chart lands (T9–T11), e.g. design colours for filled bars and areas, darker shades only for lines and markers.
- **30-10-2026** (T3 review) Badge text colours became private tokens with public overrides `--uan-text-positive/negative/neutral`, added to the public contract beside the tints. Text picks pass 4.5:1 on their tint in light, dark and high contrast (high contrast takes the light branch, since UUI's high-contrast theme sets no `--uui-color-scheme`). Also: percent formatted by Intl (da-DK "+12,4 %"), "pp" is a translation key, and hidden "improvement/decline/no change" text so meaning isn't colour-only. The unused deltaUp/Down/Flat keys were removed.
- **30-10-2026** (T4 review) `uan-empty-state` headline is styled text, not a heading. It sits inside a `uui-box` whose title is the real heading, and a fixed `h3` would have put several identical headings above their own pane title.
- **30-10-2026** (T4) FND-3 AC2 (default empty text inside a data element) stays pending until T9 and T15 add a data element. Default text is already covered by the empty state's own specs.
- **30-10-2026** (T5) Loading parts are internal elements `uan-skeleton` and `uan-loading-bar` plus `getLoadingMode(loading, hasData)`. They expose no `part` names: a styling hook on a data element would be public API that api-extractor can't see, so any hook is added by the data element itself and recorded in SPEC.md. Hosts set `--_uan-skeleton-height` (content height) on their own `:host`.
- **30-10-2026** (T6) KPI icon square uses dedicated tokens `--_uan-kpi-icon-bg/fg` (public `--uan-kpi-icon-*`), not `--uan-series-2` as PLAN T6 said: series-2 is maroon in the light theme and a dark glyph on it fails 3:1. Default is space-cadet on UUI 2 spanish-pink, 12.5:1 in every theme.
- **30-10-2026** The Phase 1 design was drawn on UUI 1 (CMS 17) colours. UUI 2 (CMS 19) changed spanish-pink (#f5c1bc → #ffe8e6, much paler) and maroon-flush (#c31d4c → #df2a5d). Everything else matches. So pink surfaces look paler than the design. Awaiting the user's call on following UUI 2 or matching the design.
- **30-10-2026** User chose CMS 19's UUI 2 spanish-pink (paler than the design's UUI 1 pink) so the package matches the rest of the v19 backoffice.
- **30-10-2026** User: KPI tile selection copies UUI's `SelectableMixin`/`uui-card` (events `selected`/`deselected`, self-toggling unless cancelled, `deselectable`, the `--uui-color-selected` border and hover fade), so product code reads the same as for UUI cards. We keep `aria-pressed`, which UUI cards lack. UUI's mixin isn't reused directly: it's only in `@umbraco-ui/uui/internal/*`, not re-exported by `@umbraco-cms/backoffice/external/uui`, so importing it would bundle a second UUI copy. New task T7b; KPI-2 grows to 9 criteria.
- **30-10-2026** User: consistency with UUI is a goal for the whole package. Added as a repo CLAUDE.md rule and ARCHITECTURE.md decision 11.
- **30-10-2026** (T7b) `selected`/`deselected` match `UUISelectableEvent` exactly: `CustomEvent` with bubbles and cancelable, not composed, with `detail` `{}` as UUI's base event sets. That overrides SPEC's general "composed CustomEvent" rule for UUI-mirrored events. `deselectable` isn't reflected, as in UUI. Adding `composed` later would be non-breaking if products nest tiles in their own shadow roots and need it.
- **30-10-2026** (T7b review) User: in dark mode the KPI tile's selected border uses `--uui-palette-malibu-light` (4.4:1 on the dark surface) instead of UUI's `--uui-color-selected` (#316dca, 2.5:1). Light and high contrast keep UUI's colour. Logged departure from `uui-card` for accessibility.
- **30-10-2026** (T7b) Departure from `uui-card`: the hover pulse only animates under `prefers-reduced-motion: no-preference`. `uui-card` always animates.
- **30-10-2026** User: element and token prefix changes from `uan` to `uax` before anything is released (elements `uax-*`, classes and types `Uax*`, CSS `--uax-*` and `--_uax-*`, translation keys `uaxAnalytics_*`). The npm scope `@umbraco-analytics` stays. Done as one refactor commit after T8.
- **30-10-2026** (T8) `uan-group-by` is our own radiogroup with UUI's look and keyboard model, not composed UUI. `uui-button-group` is only a layout wrapper with no radio role or keys, and `uui-radio` draws circles that can't be restyled into a segmented control. Mirrors `uui-radio-group`: arrows move and wrap, selection follows focus, roving tabindex, no Home/End, the group sets its own `value` then raises a bubbling, non-composed `change`. Departures: `change` carries `detail: { value }` per SPEC (UUI's detail is empty), no disabled/readonly yet. Selected segment: white on space-cadet (light, high contrast), space-cadet on malibu-light (dark). `UanGroupBy` type lives in `src/group-by/`; T9 imports it instead of redeclaring it.
