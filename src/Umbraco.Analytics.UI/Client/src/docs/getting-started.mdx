# Getting started

Umbraco Analytics UI is a set of shared backoffice charts, tables, KPI tiles and filters. Engage, Commerce and Umbraco AI use them for their analytics sections, and so can your own backoffice extension.

The components only draw. You fetch the data and pass it in.

## Install

The package comes in two parts.

| Package | Feed | What it does |
|---|---|---|
| `Umbraco.Analytics.UI` | NuGet | Puts the components on the site and adds `@umbraco/analytics-ui` to the backoffice import map. Every product on a site shares this one copy. |
| `@umbraco/analytics-ui` | npm | Types only. Add it as a dev dependency. |

1. Reference the NuGet package from your project, with a range that stays on one CMS major (see [Versioning](?path=/docs/guides-versioning--docs) for why the upper bound is `19.999.999`):

   ```xml
   <PackageReference Include="Umbraco.Analytics.UI" Version="[19.0.0, 19.999.999)" />
   ```

2. Add the types as a dev dependency:

   ```bash
   npm install -D @umbraco/analytics-ui
   ```

3. Mark it as external in your bundler, so you use the backoffice's copy instead of bundling your own. For Vite:

   ```ts
   rollupOptions: {
     external: [/^@umbraco-cms\//, /^@umbraco\/analytics-ui(\/|$)/],
   }
   ```

## Import the elements

The import map points `@umbraco/analytics-ui` at the copy on the site. One import registers every `uaui-*` element:

```ts
import "@umbraco/analytics-ui";
```

Helpers, types and constants come from the same place:

```ts
import { uauiTimeBuckets, UAUI_TABLE_CELL, type UauiSeries } from "@umbraco/analytics-ui";
```

In a template, a name that starts with `.`, like `.series`, sets a property. Pass objects and arrays that way.

Put charts and tables in a `uui-box` with `--uui-box-default-padding: 0`. They pad themselves.

## A KPI tile

You format the value. `delta` is the change against the comparison period: `18.7` is +18.7%.

```ts
html`<uaui-kpi-tile label="Revenue" value="€ 4,837.40" icon="icon-coin-dollar" .delta=${18.7}></uaui-kpi-tile>`;
```

## A chart with a date range and group by

The date range and the group by switch raise `change`. You load new points when either changes. The chart takes the range and the comparison so the two periods line up.

```ts
import type {
  UauiCompare,
  UauiDateRange,
  UauiDateRangeChangeDetail,
  UauiGroupBy,
  UauiGroupByChangeDetail,
  UauiSeries,
} from "@umbraco/analytics-ui";

@state() private _range: UauiDateRange = { from: "2026-06-01", to: "2026-06-30" };
@state() private _compare?: UauiCompare;
@state() private _groupBy: UauiGroupBy = "day";
@state() private _series: UauiSeries[] = [];

render() {
  return html`<uui-box headline="Visitors" style="--uui-box-default-padding: 0">
    <uaui-date-range
      slot="header-actions"
      .value=${this._range}
      @change=${(e: CustomEvent<UauiDateRangeChangeDetail>) => {
        this._range = e.detail.value;
        this._compare = e.detail.compare;
        this.#load();
      }}
    ></uaui-date-range>
    <uaui-group-by
      slot="header-actions"
      .value=${this._groupBy}
      @change=${(e: CustomEvent<UauiGroupByChangeDetail>) => {
        this._groupBy = e.detail.value;
        this.#load();
      }}
    ></uaui-group-by>
    <uaui-time-series-chart
      kind="area"
      group-by=${this._groupBy}
      .series=${this._series}
      .range=${this._range}
      .compare=${this._compare}
    ></uaui-time-series-chart>
  </uui-box>`;
}
```

Each series is `{ id, label, points: [{ date, value }] }`, with dates as `YYYY-MM-DD`. Points are not grouped for you: send one point per bucket, at the bucket's first day. `uauiTimeBuckets` (below) gives you those buckets.

For a metric where a fall is good (refund rate, bounce rate, average duration), add `lower-is-better` to the chart, as on `uaui-kpi-tile`. The gap shading against the compare line and the change badges in the tooltip then read a fall as good. It covers every series and the total, since one chart shows one metric.

## Hourly charts

Set `group-by="hour"` to draw one bar per hour. Offer it with `uauiGroupByOptions(range)`: a range of two days or fewer gets `["hour", "day"]`, any other range `["day", "week", "month"]`. Pass the result to `uaui-group-by` as `options`. When the current value isn't in the new list after the range changes, switch to the list's first option. The chart itself draws hourly for any range, so you can break the two-day limit on purpose.

```ts
import { uauiGroupByOptions, uauiTimeBuckets, type UauiGroupByChangeDetail } from "@umbraco/analytics-ui";

const options = uauiGroupByOptions(range); // ["hour", "day"] for a one or two day range
if (!options.includes(this._groupBy)) this._groupBy = options[0];

html`<uaui-group-by
  .options=${options}
  .value=${this._groupBy}
  @change=${(e: CustomEvent<UauiGroupByChangeDetail>) => {
    this._groupBy = e.detail.value;
    this.#load();
  }}
></uaui-group-by>`;

// One query per bucket: `start` and `end` are UTC instants, so send them as they are.
// A week or month bucket at the edge of the range reaches past it: clip with `days` or the range.
// Range Nov 5, browser at UTC+1: the first hour starts at local midnight, which is 23:00 UTC the day before.
const buckets = uauiTimeBuckets(range, "hour"); // [{ start: "2026-11-04T23:00:00.000Z", end: "2026-11-05T00:00:00.000Z", days }, ...]
```

At hour level:

- A point's `date` is a moment, such as `"2026-11-05T13:00:00Z"`. The chart puts it in the browser's local hour that contains it. A date-time without a zone is local time. A plain date is local midnight.
- Plot each point at its bucket's `start` from `uauiTimeBuckets`. They are UTC instants, so on the day clocks go back the repeated 2 AM stays two bars.
- A bucket is the local hour. In a half-hour zone (India, +5:30) an hour counted in UTC straddles two bars.
- Compare lines up by wall-clock hour: 2 PM sits under 2 PM of the compare period, even when one of the days has 23 or 25 hours.
- Day, week and month don't change. A date-time there is still cut to the day it starts with.
- A one-day range reads as one date in `uaui-date-range` and `uauiFormatDateRange` ("Nov 5, 2026"), not "Nov 5, 2026 to Nov 5, 2026".

## Now and incomplete data

Set `now` to draw a labelled line at the current moment. It takes a date or a date and time, read as a moment: a date-time with a zone is that instant, one without is local time, and a plain date is that local day. The line sits in the middle of the bucket that contains it, and no line is drawn when no bucket does. The label says "Now" with `group-by="hour"` and "Today" otherwise. `now` replaces the old `today` property.

`incomplete-from` is read as a moment in the same way. With `group-by="hour"`, everything from the hour that contains it is hatched and faded. Set both to mark the current hour as incomplete.

```ts
html`<uaui-time-series-chart
  group-by="hour"
  .series=${this._series}
  now=${new Date().toISOString()}
  incomplete-from=${new Date().toISOString()}
></uaui-time-series-chart>`;
```

## Today and yesterday presets

`uaui-date-range` knows the built-in preset ids `today` and `yesterday`, but doesn't list them by default. Add them to `presets` to offer them. A product that applies the switch-to-first-option rule above opens "Today" on hours, because a one-day range gives `["hour", "day"]`.

```ts
html`<uaui-date-range
  .presets=${[{ id: "today" }, { id: "yesterday" }, { id: "last-7-days" }, { id: "last-30-days" }, { id: "custom" }]}
></uaui-date-range>`;
```

## A table

Each column names the cell that shows it.

```ts
import { UAUI_TABLE_CELL, type UauiTableColumn, type UauiTableRowClickDetail } from "@umbraco/analytics-ui";

const columns: UauiTableColumn[] = [
  { key: "title", label: "Page", elementName: UAUI_TABLE_CELL.link, meta: { hrefKey: "url" }, searchable: true },
  { key: "views", label: "Views", elementName: UAUI_TABLE_CELL.share, align: "end", sortable: true, sortAs: "number" },
];
const rows = [{ title: "Home", url: "https://example.com/", views: 1240 }];

html`<uaui-data-table
  label="Top pages"
  .columns=${columns}
  .rows=${rows}
  row-key="url"
  clickable-rows
  @row-click=${(e: CustomEvent<UauiTableRowClickDetail>) => this.#open(e.detail.row)}
></uaui-data-table>`;
```

`row-key` names the field that identifies a row, so `compareRows` (last period's rows) can be matched to `rows`. When it takes more than one field, set the property to an array, such as `.rowKey=${["productReference", "productVariantReference"]}`: a row matches when every field matches, and a field a row lacks counts as empty.

Replace `rows` and `columns` with new arrays to update the table. Changing them in place isn't noticed.

## Date helpers

Small functions for the dates around the picker, so each product doesn't write its own. A range is `{ from, to }` in ISO dates: a `UauiDateRange` or a `UauiCompare` fits. A range that isn't valid (an unreal date, or `to` before `from`) gives `undefined`, or an empty list for the day and bucket helpers.

```ts
import { uauiCompareFor, uauiTimeBuckets, uauiFormatDateRange } from "@umbraco/analytics-ui";

const range = { from: "2026-05-25", to: "2026-06-23" };
const compare = uauiCompareFor("previous-period", range); // { mode, from: "2026-04-25", to: "2026-05-24" }

// One chart point per bucket, plotted at the bucket's `start`.
const points = uauiTimeBuckets(range, "week").map(({ start, days }) => ({ date: start, value: sum(days) }));

// The label `uaui-date-range` shows, for the chart's compareLabel. Pass your element's `this.localize`.
html`<uaui-time-series-chart .compareLabel=${compare && uauiFormatDateRange(this.localize, compare)}></uaui-time-series-chart>`;
```

| Function | Gives |
|---|---|
| `uauiPresetRange(id, today)` | The dates a built-in preset of `uaui-date-range` (including `today` and `yesterday`) gives as of `today`. `undefined` for `custom`, an unknown id, or a `today` that isn't a real date. |
| `uauiPreviousPeriod(range)` | The same number of days straight before `range`. For a range with `preset: "this-month"`, the same days of the previous month. |
| `uauiPreviousYear(range)` | The same dates one year earlier. |
| `uauiCompareFor(mode, range)` | A `UauiCompare` for `previous-period` or `previous-year`. `undefined` for `custom`. Pass the saved range, with its `preset`, to match the dialog's month-aligned compare for `this-month`. |
| `uauiDaysIn(range)` | Every ISO date in `range`, both ends included. |
| `uauiGroupByOptions(range)` | The `uaui-group-by` options for `range`: `["hour", "day"]` for two days or fewer, otherwise `["day", "week", "month"]`. |
| `uauiTimeBuckets(range, groupBy, { weekStart })` | `{ start, end, days }[]` for `hour`, `day`, `week` or `month`. `end` is where the next bucket starts. An `hour` bucket's `start` is a UTC instant. |
| `uauiFormatDateRange(localize, range, { showYear })` | Text such as "May 25, 2026 to Jun 23, 2026" in the user's culture. One date, such as "Nov 5, 2026", when `from` equals `to`. |

Weeks start on Monday. For another first day, pass `weekStart` to `uauiTimeBuckets` and the same value as `week-start` on the chart. It is 1 (Monday) to 7 (Sunday), like `new Intl.Locale(culture).getWeekInfo().firstDay`. Any other value is read as Monday.
